# 📖 Coding Standard & Convention

**Version:** 1.0  
**Last Updated:** July 25, 2026  
**Purpose:** Ensure consistency across all platforms (Backend, Mobile, Web)

## Backend (NestJS + TypeScript)

### Naming Convention

**Files:**
```
auth.service.ts          (feature name + purpose)
create-user.dto.ts       (action + entity + type)
user.entity.ts           (entity name + entity)
```

**Classes & Functions:**
```
export class UserService {}        // PascalCase for classes
export async createUser() {}        // camelCase for functions
private readonly config: Config;    // camelCase for properties
```

**Constants:**
```
const MAX_RETRY_ATTEMPTS = 3;       // CONSTANT_CASE
const API_TIMEOUT_MS = 5000;
```

### File Structure

```
modules/
├── auth/
│   ├── auth.service.ts
│   ├── auth.controller.ts
│   ├── auth.module.ts
│   ├── guards/
│   │   └── jwt.guard.ts
│   ├── strategies/
│   │   └── jwt.strategy.ts
│   └── dto/
│       └── create-user.dto.ts
```

### Error Handling

```typescript
// ✅ Good
throw new BadRequestException('Email already exists');

// ❌ Bad
throw new Error('Email already exists');
throw { message: 'Email already exists' };
```

### API Conventions

```
POST   /users              (create resource)
GET    /users/:id          (get single resource)
GET    /users              (list with pagination)
PUT    /users/:id          (replace resource)
PATCH  /users/:id/status   (partial update)
DELETE /users/:id          (delete resource)
```

### Commit Message Format

```
feat: add user registration endpoint
fix: fix location anonymization bug
refactor: simplify auth service
docs: update API documentation
test: add user service tests
chore: update dependencies
```

**Files & Classes:**
```

final authProvider = ...       (camelCase for variables)
```

### Error Handling

```dart
// ✅ Good
try {
  final result = await repository.login(email, password);
} on SocketException {
  // Handle network error
} on FormatException {
  // Handle parsing error
}

// ❌ Bad
try {
  // code
} catch (e) {
  print(e);
}
```

### Riverpod Providers

```dart
// Service provider
final authServiceProvider = Provider<AuthService>((ref) {
  return AuthService();
});

// Async provider
final userProvider = FutureProvider<User>((ref) async {
  return ref.watch(authServiceProvider).getUser();

// Notifier
final userNotifierProvider = StateNotifierProvider<UserNotifier, UserState>((ref) {
  return UserNotifier();
```

```javascript

  type: 'auth/setUser',
  payload: user

// Slices
const authSlice = createSlice({
  name: 'auth',
  initialState: {},
  reducers: {}
```

### Error Handling

```javascript
// ✅ Good
async function loginUser(email, password) {
  try {
    const response = await api.post('/login', { email, password });
    return response.data;
  } catch (error) {
    if (error.response?.status === 401) {
      throw new Error('Invalid credentials');
    }
    throw new Error(error.message || 'Login failed');
  }
}

// ❌ Bad
async function loginUser(email, password) {
  const response = await api.post('/login', { email, password });
  return response.data;
}
```

## All Platforms

### Logging Convention

```
[ERROR] Feature: Message       (errors only)
[WARN]  Feature: Message        (warnings)
[INFO]  Feature: Message        (general info)
[DEBUG] Feature: Message        (development only)
```

### Comments Convention

```typescript
// ✅ Bad comment
const x = 5; // set x to 5

// ✅ Good comment
// Retry limit for API calls (exponential backoff applied)
const MAX_RETRIES = 5;

// ✅ Complex logic needs explanation
// Use Haversine formula to calculate distance between two coordinates
// in kilometers. Radius Earth ~6371km
const distance = calculateDistance(lat1, lng1, lat2, lng2);
```

### Null & Undefined Handling

```typescript
// ❌ Avoid
if (user) { }

// ✅ Explicit
if (user !== null && user !== undefined) { }
if (user != null) { }  // JS trick: works for both null and undefined

// ✅ Type safety (TypeScript)
if (user) { }  // works when user type excludes null
```

### Code Review Checklist

Before submitting PR:

```
- [ ] Code follows naming convention
- [ ] No hardcoded values (use environment variables)
- [ ] Error handling complete
- [ ] No console.log() left in code
- [ ] Comments added for complex logic
- [ ] No commented-out code
- [ ] Tests written (if applicable)
- [ ] Documentation updated (if needed)
```

### Forbidden Patterns

**ALL PLATFORMS:**
- ❌ Never hardcode API URLs → Use environment variables
- ❌ Never log sensitive data → Remove before commit
- ❌ Never use `var` → Use `let`/`const` (JavaScript) or `final` (Dart)
- ❌ Never catch errors silently → Always log or re-throw
- ❌ Never commit commented code → Delete or create issue

## Git Workflow

### Branch Naming

```
feature/auth-login        (new feature)
feature/jobs-search       (new feature)
fix/auth-token-refresh    (bug fix)
refactor/location-service (refactoring)
docs/api-endpoints        (documentation)
chore/update-deps         (dependencies)
```

### Commit Rules

```
✅ DO:
- One logical change per commit
- Descriptive message (50 chars title)
- Reference issue if exists: "fix: resolve #123"

❌ DON'T:
- Commit formatting fixes with logic changes
- Mix features and fixes in one commit
- Use vague messages ("fix bug", "update code")
```
