## Frontend Changes

### Real API Integration

**Old (Mock):**
```javascript
setTimeout(() => {
  setJobs([...mockJobs]);
}, 600);
```

**New (Real):**
```javascript
fetch('/api/jobs/search/bounds', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify(searchPayload),
})
  .then(response => response.json())
  .then(data => setJobs(data.jobs))
  .catch(err => setError('تعذر تحميل الوظائف'));
```

### Caching Strategy

```javascript
const cacheRef = useRef(new Map());
const CACHE_DURATION = 5 * 60 * 1000; // 5 minutes

// Cache key based on bounds
const cacheKey = `${north}-${south}-${east}-${west}`;

// Check cache before API call
const cached = cacheRef.current.get(cacheKey);
if (cached && Date.now() - cached.timestamp < CACHE_DURATION) {
  setJobs(cached.jobs);
  return;
}

// Cache after API response
cacheRef.current.set(cacheKey, {
  jobs: data.jobs,
  timestamp: Date.now(),
});
```

### Error Handling

- Display error message with red background
- Show "إعادة محاولة" button
- Track retry count (for analytics later)
- Keep previous results visible during error

```jsx
{error && (
  <div className="error-message">
    <p>{error}</p>
    <button onClick={handleSearchThisArea}>🔄 إعادة محاولة ({retryCount})</button>
  </div>
)}
```

### Loading State Improvement

**Old:** Clear jobs when loading

**New:** Keep previous results while loading
```javascript
{isLoading && jobs.length === 0 ? (
  <div>Loading...</div>
) : jobs.length === 0 ? (
  <div>No jobs</div>
) : (
  // Show previous results
)}
```

## Backend Changes

### New Endpoint

**POST `/api/jobs/search/bounds`**

Searches jobs within geographic bounds with filtering support.

**Request:**
```json
{
  "bounds": {
    "north": 34.5,
    "south": 32.0,
    "east": 45.0,
    "west": 43.0
  },
  "zoom": 12,
  "center": { "lat": 33.3, "lng": 44.3 },
  "filters": {},
  "limit": 100,
  "offset": 0
}
```

**Response:**
```json
{
  "success": true,
  "meta": {
    "timestamp": "2024-01-15T...",
    "searchArea": { "north": 34.5, "south": 32.0, "east": 45.0, "west": 43.0 }
  },
  "stats": {
    "totalFound": 182,
    "returnedCount": 100,
    "filteredOut": 82
  },
  "jobs": [
    {
      "id": "...",
      "latitude": 33.3136,
      "longitude": 44.3615,
      "company": "Tech Solutions",
      "title": "Senior Developer",
      "salary": "6000-8000",
      "salaryMin": 6000,
      "salaryMax": 8000,
      "employmentType": "full-time",
      "category": "IT",
      "status": "active",
      "createdAt": "2024-01-10T...",
      "updatedAt": "2024-01-15T...",
      "description": "نبحث عن مطور React",
      "skills": ["React", "Node.js", "TypeScript"],
      "applicants": 12
    }
  ],
  "pagination": {
    "limit": 100,
    "offset": 0,
    "total": 182,
    "hasMore": true
  }
}
```

### Database Query

Uses spatial queries on `anonymizedLatitude` and `anonymizedLongitude`:

```sql
SELECT * FROM jobs
WHERE isActive = true
AND anonymizedLatitude BETWEEN :south AND :north
AND anonymizedLongitude BETWEEN :west AND :east
AND (conditions for filters...)
ORDER BY createdAt DESC
LIMIT 100 OFFSET 0;
```

### Transformation

Jobs returned from database are transformed to match frontend spec:

```typescript
{
  id: job.id,
  latitude: parseFloat(job.anonymizedLatitude),
  longitude: parseFloat(job.anonymizedLongitude),
  company: job.company.name,
  title: job.title,
  salary: `${job.salaryMin}-${job.salaryMax}`,
  salaryMin: job.salaryMin,
  salaryMax: job.salaryMax,
  employmentType: job.jobType,
  category: job.category,
  status: job.isActive ? 'active' : 'inactive',
  createdAt: job.createdAt.toISOString(),
  updatedAt: job.updatedAt.toISOString(),
  description: job.description,
  skills: job.skills || [],
  applicants: job.applicantsCount || 0,
}
```

## Database Optimization

### Indexes Required

For optimal performance with large datasets:

```sql
-- Spatial index on coordinates
CREATE INDEX idx_jobs_location ON jobs(anonymizedLatitude, anonymizedLongitude) USING GIST;

-- Status + active filter
CREATE INDEX idx_jobs_status ON jobs(isActive, createdAt DESC);

-- Combined index for bounds + status
CREATE INDEX idx_jobs_bounds_active ON jobs(anonymizedLatitude, anonymizedLongitude, isActive);
```

### Query Performance

- **Bounds query:** ~10-50ms (with index)
- **Result transformation:** ~5-20ms (depends on count)
- **Total:** ~15-70ms for 100 jobs

## Error Scenarios Handled

### Network Error
- Show: "تعذر تحميل الوظائف في هذه المنطقة"
- Action: Retry button available
- Result: Keep previous jobs visible

### Invalid Bounds
- Backend returns: 400 Bad Request
- Frontend shows: Error message
- User can: Pan/zoom map and retry

### Timeout (>10s)
- Frontend: Treat as error after 10s wait
- Show: Error message
- Retry: User can click retry button

### No Results
- Backend returns: Empty jobs array (200 OK)
- Frontend shows: "لا توجد وظائف في هذه المنطقة"
- No error - this is valid state

## Caching Strategy

### Cache Key
```javascript
const cacheKey = `${north.toFixed(4)}-${south.toFixed(4)}-${east.toFixed(4)}-${west.toFixed(4)}`;
```

Bounds rounded to 4 decimal places (~11 meters precision).

### Cache Duration
5 minutes = reasonable balance between:
- **Freshness:** New jobs appear within 5 minutes
- **Performance:** Avoid redundant API calls
- **Server Load:** Reduced when user pans around

### Cache Invalidation

Currently manual (on 5-min expiry). Future improvement:

```javascript
// Option 1: WebSocket notification on new job
socket.on('job:created', () => {
  cacheRef.current.clear(); // Clear all cache
});

// Option 2: Cache tags by category/location
cacheRef.current.set(cacheKey, {
  jobs,
  tags: ['IT', 'Baghdad'], // By category/area
  timestamp,
});
```
